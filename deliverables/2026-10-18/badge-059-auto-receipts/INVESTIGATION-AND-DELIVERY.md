## 静态链路证据

| 环节 | 实际机制与本批证据 |
| --- | --- |
| 收件/能力协商 | cflocal2-adapter.js readNext 在 current generation 协商 care_capabilities 后读取 events；firmware local2_wire.c 对清洁 FIFO 头另有当前 session 门控。缓存若仍记“已协商”而设备返回 blocked，旧代码直接抛错并停同步。 |
| 手机计划/持久提交 | offline-device-events.js 顺序执行 source 校验、原规则计划、digest、Native seal、WebStorage/画面投影、durable.confirm，之后才能调用 acknowledge。原生文件通过 AtomicFile、fsync/目录同步形成持久证据。本次 46 未进入持久结果。 |
| ACK 发送/重放 | adapter 的 sendPending 先持久保存原 id/seq/data，再发 ACK；还要严格核对设备原终态和手机摘要，最后持久推进手机日志。旧协调器普通 pump 看见 retained pending 会要求用户显式重试；原 reconnect 分支已有自动 retry，不能说所有重连都不恢复。 |
| 固件出队 | local2_core.c l2_ack_event_result 只允许当前 FIFO 头与合法收据原子更新终态、lastAck、队列及 request seq；没有无收据出队。本批未修改此规则。 |

## 本批最小变更

1. 完整删除首页重复猫爪对象、注册热区、条件启用和点击跳照料分支；保留原滑动入口。不是单纯隐藏按钮。
2. 首页与锁屏正常连接时不再显示“待确认”协议文案；断连持续 15 秒的小提示保留，只有确有持久事件时才写“离线·已记下”。真实数量仍可在状态/设备详情查看，改为“待同步”。睡觉记录页去掉要求等手机确认的文案，不因此把猫改成真实睡眠；不新增用户确认步骤。照片里的“完成动作后保存，等手机确认”照料入口说明在 058 已删除，本批保留删除结果。
3. 顶部完整蓝牙图形替换为统一原生矢量链环连接标记，以真实 BLE 已连接且订阅状态绘制连接/断开；没有声称 Wi-Fi 业务已实现或新增连接通道。位置沿用 058 顶部圆边。
4. 协调器在已授权的当前设备/generation 下自动恢复 Native 已持久保存的原命令。ACK 仍需原持久结果核对，snapshot 仍需同猫；重放严格沿用原 id/seq/data，不制造收据、不重新结算、不清队列。原手动修复入口仅作为异常重试，不是正常确认步骤。
5. 设备明确返回清洁协商 blocked 时，同一 owner/generation 自动清除 RAM 协商缓存、重新协商 **一次** 并重读原 FIFO 头；不放宽固件门控，不跳头，不修改事件。持续拒绝或身份/存储不安全仍停止并保留字节。
6. 仅增加被动、去标识的同步阶段日志：source/read_event/plan/digest/native_commit/project/confirm_receipt/ack，及 source_busy/cooldown 等延后阶段。用于下一次真实流程定位，不运行诊断脚本、不采集输入、不记录私密存档正文。

手机仅改三个同步模块及它们的 preview/assets 镜像、必要版本号：0.4.6-auto-receipts / code37。生产 APK 与已安装 045 比较，**assets 差异仅这三个同步文件**；小镇、圆环、游戏、模型等其余 assets 字节一致，未运行全量素材重建脚本。原包 ID 与签名证书保持。

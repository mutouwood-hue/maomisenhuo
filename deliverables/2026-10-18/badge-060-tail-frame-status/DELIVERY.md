# 060：滑动末帧交接与主屏状态元素

固件版本 `0.6.0-tail-frame-status`。沿用 b8ca479 加未提交 056–059，保留用户已认可的 058/059 滑动手感与时间结构。未修改手机 046、ACK 链路、圆环业务、养成规则或模型；小镇、按键回主屏、点按加好友及相遇仍不纳入。本批无 commit/push/reset/清理。

## 真实完成的源码修改

### 只补滑动末帧

静态代码明确显示：旧 `settle_done` 在 LVGL 动画完成回调中立即 `drag_cancel`，隐藏 `peek_root` 并恢复真实树。因此动画刚把目标快照移到零偏移时，显示刷新还可能没有绘制/传输该最终位置；接着 UI 立即恢复轮询与动画，交接也可能只有局部区域失效。

060 只增加两个末帧交接阶段：

1. 保留最终位置的完整快照，整屏失效并请求刷新；收到真实 `LV_EVENT_RENDER_READY` 后，由既有 UI 定时器等待 LVGL 的 volatile `flushing` 变为 0，再提交真实页面。
2. 在一个 GUI 轮次内恢复真实树/姿态，再整屏失效一次；其首个完整实时帧完成绘制、最后传输释放后，才恢复普通动画和 UI 轮询。

这两段只等待显示实际工作完成，不新增手势长按/计时门槛。没有改 160px 距离阈值、方向锁定、1:1 跟随、90ms 取消、150ms 提交及线性路径；`badge_gesture.c/.h` 字节保持。已接受的时间 x/y、字号及天气/连接位置也未重排。圆环仍独占触摸，BLE 收件和落盘仍在原独立任务。

末帧等待只轮询锁定版本 LVGL 9.5 的真实传输所有权；没有手工调用 flush_ready、改写 DMA 缓冲或接管驱动回调。保留现有 48 行 PARTIAL 双缓冲及 TE 设置，不将软件整帧交接宣称为面板硬件原子换帧或物理无撕裂证明。是否消除用户最后一点割裂，仍需用户实机观察。

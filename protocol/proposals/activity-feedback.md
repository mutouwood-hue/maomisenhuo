# 实际活动反馈扩展提案（待产品负责人确认）

状态：提案；没有修改冻结的 v1，也没有以此声称吧唧出游功能已实现。

## 目的和边界

让手机已真实开始、取消或成功结算的照料、出游和诊所流程驱动吧唧的彩色场景、原猫动作和短消息。场景只使用用户选择的花园/森林/河边等游戏地点，不使用定位、环境、语音或真实传感器。

当前 v1 快照只有宠物标识、版本、数值、金币与更新时间。仅由数值变化猜测正在喂食或出游会产生错误反馈，因此需要明确活动字段。

## 建议契约

在双方明确协商支持的协议修订版中，快照增加可选 `activity`：

| 字段 | 取值/约束 |
|---|---|
| id | 原生生成并持久化的 UUID；同一次活动保持不变 |
| kind | `care`、`outdoor`、`clinic` |
| action | 封闭枚举，逐项映射现有原型动作；未知值拒绝 |
| phase | `started`、`active`、`completed`、`cancelled` |
| location | `room`、`garden`、`forest`、`river`、`clinic` |

整条快照仍受持久 revision 排序、宠物绑定、2048 字节含换行限制。开始必须对应真实原生会话；完成必须与奖励/扣费同一存档事务提交；取消不得产生奖励。BLE 离线不阻塞手机玩法，重连仅传最新已提交状态，不播放离线期间的虚构实时进程。

当前原型只有成功结算后回到小屋，没有独立的真实“返程中”阶段，因此当前完成态只能显示“回家啦”的结果。若要展示返程过程，须先确认并实现原生真实阶段，再扩充契约；不能在收到 completed 后补播为实时返程。

## 设备处理与恢复

- 活动标识、阶段与快照原子持久化。重复帧只能重发确认，不能重复播放一次性完成反馈或重复奖励。
- 开机读到历史完成态只显示静态结果；首次同步不能将旧记录当作刚发生的动作。过期活动不得无限显示进行中，需定义有效期与时钟无效时的静态回退。
- 固件 NVS 结构采用可迁移版本，保留现有宠物绑定、队列事件 ID、计数与 bond。迁移失败阻断覆盖并显示恢复提示，不擦除 NVS。
- 保留原猫两种真实源姿态，以轻量位移、表情/短文案配合原型配色；不称完整 3D 动画。466 圆屏安全区与高对比度优先。

## 验收

实际开始/取消/成功结算逐项核对手机存档、协议帧与吧唧；覆盖离线重连、重复通知、进程中止、掉电、旧 NVS 升级以及历史状态不重播。模拟器不能代替真实 BLE、屏触、功耗与掉电验收。

## 最少待确认

产品负责人确认扩展方向及最先支持的实际动作枚举后，冻结独立修订契约和迁移夹具，再修改两端。全量 PRD 需求没有因本提案而删除。

固件独立迁移与历史回放评审见 [ACTIVITY-PROPOSAL-REVIEW.md](../../firmware/ACTIVITY-PROPOSAL-REVIEW.md)。其中原始 V1 布局冻结、V2 读回后启用、失败不能回退过期 V1、降级转换和无可信时钟租约均应列为修订契约的前置条件。

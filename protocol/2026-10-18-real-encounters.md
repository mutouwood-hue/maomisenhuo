# 062 / 048：真实吧唧暗号相遇

来源：Notion 原 PRD 8.3、8.4、13.10；2026-10-18 相遇纠正页。敲暗号、连点暗号的数值仍是 PRD 初值；本文件不是双机验收报告。当前只有一台吧唧，禁止用模拟或 NPC 作真实相遇证据。

## 输入与硬件

- PWR = AXP2101@0x34。检查 IC_TYPE 0x03=0x4a；只读/使能 0x41 bit3，读/清 0x49 的 PWRON IRQ。仅 SHORT 且无 LONG 才发一次事件。RW1C 成功才入队；I2C 在独立任务，GUI 不轮询电源总线。
- 上键短按：AOD/息屏唤醒到主屏；其他页回主屏；主屏仅刷新空闲时间。没有新增短按锁屏。自动锁屏和原触摸唤醒保留。OFFLEVEL、关机、供电和充电寄存器不改，长按关机保留给 PMIC。
- 下键 GPIO0 由已有 espressif/button 消抖；DOWN/HOLD/UP 只有一个 UI 消费者。待机按下只唤醒，后续 HOLD/UP 同次消费；亮屏长按 1 秒进入暗号，松手不再算一次敲击。暗号页短按产生节奏；主屏短按沿用摸摸；其他页短按不导航。语音仍关闭。
- 敲暗号：双方进入，较小设备 ID 一方先敲，另一方跟敲。4–8 下，60ms 去抖，停 1.2 秒结束；对方收到完整节奏后 5 秒内完成跟敲。按原 HTML judge：相邻间隔按总时长归一，绝对差不超过 0.15；总时长差 / 两者较大值不超过 0.30。双方总就绪窗口 15 秒。比较不使用两机绝对时钟。
- 连点暗号：圆周八点 + 中心一点，0..8 编码，至少4、最多9个不重复点，顺序完全相同。触摸连点或连线，提交后不可改；匹配后另按确认。
- 收发、比对和本机输入不是成功。两边均须在各自吧唧确认。

## 发现、连接与协议

沿用单 NimBLE host、原 peer GATT UUID、20字节可靠分片与 FIFO 重传。manufacturer schema 改为3（23字节）；旧 schema2 的单按钮确认设备不会加入此会话。仍仅主动进入暗号时发现，RSSI 门槛沿用 -65dBm；这是近场信号筛选，未校准为精确1米测距。普通附近广播不产生好友或奖励。

应用消息上限160字节。HELLO131字节含设备ID、每次连接新挑战、预期广播token、主动进入时生成的16字节arm随机数、方法、该peer上次持久事务证明与阶段，以及本机快照已有的猫名/花色。未交换真实姓名、联系方式、定位、声音、性别、年龄、配饰或新账号身份。挑战绑定当前连接；旧连接 CONFIRM/INPUT/DONE 不能直接重放。

会话ID取按设备ID排序后的 `ID_A || arm_A || ID_B || arm_B` 的 SHA256 前16字节。两边得到同一ID。INPUT含方法、次数、节奏间隔或点序；收到后各自比对。CONFIRM必须携带相同会话ID与一致的主节奏/印章证明，且本机确实匹配并经用户确认后才接受。不是收到确认包就建好友。

## 持久阶段与恢复

CFL2存储升级为4，兼容读取旧2/3；没有 reset、擦存档、重建owner或复用counter。新增每个peer最近事务证明及独立 encounter FIFO 事件。旧照料、野花终态与ACK水位按原字节语义保留。

1. 双方匹配、双方确认后，先原子保存 `prepared(1)` 证明，不排手机事件。
2. 收到对方同证明的持久prepared后保存 `committed(2)`，仍不排手机事件。
3. 收到对方持久committed后，将本机阶段设为 `settled(3)`，与唯一事件号/完整相遇证明在同一NVS blob原子提交。
4. 收到对方settled才显示双方已保存。继续发最终回执3秒后退出发现。

确认前取消、输入不匹配或15秒超时关闭发现，不写相遇记录。双方进入保存后确认不可撤回，返回主屏不伪装取消成功；断线后持久证明继续留在原存档，下次双方进入恢复。两边有相同未完成证明时恢复阶段；只有一边有未完成证明时，未持久同意的一方必须重新输入匹配暗号并确认。不同未完成事务冲突则停止，不覆盖旧证明。传输重试、阶段重试、相同会话重连均复用同一ID；settled再收不会新增事件。

最多32个peer，FIFO原上限200、存储上限8192字节。字节容量不足返回queue_full并保留原状态，不以清队列或擦NVS解决；已有事件经原手机持久收据ACK释放后才能继续。新格式写入后旧061不认识schema4，不能直接降级到旧固件。

## 手机权威结算

`encounter_v1`能力加 CFLOCAL2 `kind=encounter`：设备事件ID/序号、peer ID、共同会话ID、方法、原始mark、已有猫名/花色、peerComplete=true、可靠时间或null。适配器和消费者均校验。时间缺失不制造历史时间；手机保留设备时间及本机入账时间。

复用原 `friendProgress`（从原completeMeet抽出）和 `worldGrow/worldState`，直接写既有pg-social-v1好友、节奏/印章、手记和世界log。世界仍同一人每天一次、同日固定3–5次上限；新朋友中变化、老朋友小变化。无真实相遇不新增世界种子，NPC新互动不再调用真实世界成长。旧原型历史不删除。

原先peer协议只有每对一次的首次野花，本版将这项固定互赠约定纳入schema3的双向暗号确认；手机以永久pair记录和已有真实野花收据去重，首次最多野花1，不调用NPC随机回礼。其他盲盒/图鉴交换、自定义送礼、联机生蛋和联系方式交换尚未进入真实设备协议，真实好友页面禁用这些入口，不能由NPC规则代算。

新增 `nativeEncounters[peerId:encounterId]` 永久去重，外层仍沿原事件ledger、native完整game/social事务落盘、投影、带原摘要/终态的连续FIFO ACK；重复事件复用原收据。不是先ACK再写好友。完整备份按原契约携带这些社交数据。

相遇页、好友、图鉴、礼物记录与世界均沿用既有页面；真实吧唧说明和结果在附近页顶部，NPC置于明确的游戏角色分区。浏览器双窗口不再模拟真实BLE；扫码入口、旧遇见链接确认、手机倾角/指针Fate生成均退出产品路径。为保持原社交事务隔离，互动页打开时等待消费；回小屋后自动补传，再打开看记录。原生结算后调用原buildWorld3D投影已保存变化，不改暂停的小镇。

## 明确未交付的感知方式

缘分擦肩保留独立关闭开关和独立记录语义，历史原型记录明确标记来源，不作真实记录。原定义为默认关闭、双方后台蓝牙范围内相对静止基线瞬时偏离>=8度、相差<=3度、连续0.3秒、非好友、每对一次。原PRD仍将广播对时、独立功耗、正式采集授权列待定，本版不初始化IMU、不扩展后台广播/采集范围；真实擦肩采集未实现/未部署，需用户决策后另批推进。当天原型中的每日3次不自动当成正式上线决策。

当面晃一晃静态核对未找到完整真实双吧唧链路，手机旧Fate仅倾角/拖动与生成NPC样本，因此不保留为已完成备用方式。扫码维持取消。

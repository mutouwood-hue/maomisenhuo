# App连接与事件传输接入边界（提案，尚未联调）

## 当前行为

[App adapter](<../main/net/app_link.c>)目前只管理BLE社交层，没有手机认证协议。因此已采取失败关闭：

- GAP连接、GATT服务可用、peer完成社交握手均**不等于已认证App**。
- [手机状态查询](<../main/net/app_link.h>)当前返回false，不自动完成配对，不开启自由语音在线分支。
- 新接通的FSM动作保存在[离线事件队列](<../main/net/badge_events.c>)，不向附近设备/未知手机发送。
- 这是一项安全性纠正，但意味着App补传仍不可用；不是“联网能力已完成”。

## 下一阶段的契约需求

App接入必须确认以下事项后才接回真实发送：

1. 身份：手机归属绑定、会话认证、断开即撤销session；密钥不由公开设备ID派生，不写日志。
2. 输入：社交和App消息的类型空间/版本区分，唯一RX分流；未知/越界/坏UTF-8包不改模型。
3. 线程：NimBLE回调只投递有界消息，由LVGL主线程应用，不能跨线程修改FSM/游戏/事件队列。
4. 时间：App同步Unix秒及时区偏移，区别未同步状态；事件clock推进与flash写入分开。
5. 发送：确认身份后才允许取队列，按每tick预算发送；发送失败不移除队头。
6. 收到与持久化：GATT send成功不等于App已经收到/结算。8B负载无sequence，不能保证exactly-once。建议传输信封session+sequence+ACK，由双方确认，保留现有8B事件内容；不能私自修改旧事件表。
7. 重传：重启/重连、已确认但NVS未更新窗口、离线200条覆盖策略需要App幂等协议与可见数据丢失说明。
8. 初始化：无线失败不影响本地输入、FX、保存。认证缺失保持fail-closed；开发模拟必须显式开启且不能生成发布版本默认特权。

## 待双方确认（不臆造消息编号）

- App握手/绑定的消息结构与安全方式；现有手机端库和GATT约定。
- 下行快照字段/长度/版本、分片策略、错误码与回复关联。
- 8B事件信封和ACK范围、序号持久化/去重生命周期。
- QR一次性token发行/校验、有效期与双方结果通知。
- 第15引导结束事件编号与客户端兼容演进。

## 扫码入口现状（2026-10-13）

生产[UI](<../main/ui/badge_ui.c>)已禁止绘制BE_QR原有伪随机模块图，改显示“扫码尚未接入”。[旧绘制器](<../main/ui/badge_paint.c>)保留参考图案函数仅供旧黄金测试，不代表有效QR，不能将其连接到生产身份流程。

接入前须提供发行者、payload版本/长度、token有效期与单次使用、设备归属绑定、签名或服务端校验、撤销/刷新条件。使用标准QR编码器和真实手机扫码解码验证；生成模块外观/三个定位块不等于QR可解码，更不等于绑定成功。无效/过期/已使用/错设备token不得推进binding_verified或社交确认。没有App代码与契约时保持入口不可用，不能编造URL/token。

## 验收

- 未认证手机、social peer均拿不到照料事件。
- 断开后原session不可复用，重连必须认证。
- 认证App收到正确FIFO记录，坏包/ACK超范围不删除数据。
- 模拟send成功不标App联调通过；真实手机写入/通知/ACK与重连后去重分别留证据。

当前已由[生产桥接组合测试](<../tests/host/test_badge_runtime.c>)覆盖：实际adapter在模拟已连接radio下仍报告无App特权，队列不减少且无动作帧发送。真实认证与ACK为下一阶段工作。

## 3. 优先级与关键路径

M2不是仅加页面：目标为自研AMOLED吧唧V1 + 联机生蛋 + 近场交换 + 图鉴。建议拆成 M2-A/B/C/D 交付包，属于执行拆分，不重命名PRD里程碑。

关键路径：**可信设备归属 → 双向遇见确认 → 云端资产账本 → 原子交换/礼物 → 真实玩家联姻 → 图鉴谱系 → 线下试养**。

硬件自研、电源测试及麦克风专项并行推进；Fate与真实收费不得挤占主路径。M2进入条件原为三周验证Go，本轮未见结果证据：需提供留资≥5%、D7≥30%、在意/想念≥40%、小额付费≥2%的报告；若尚未满足，可批准工程预研，但不能写成产品Go已通过。

### M2-A：底座收尾与验收门禁（建议1–2周）

- 固定V2为当前集成入口；旧固件保留历史回归，不把两个实现同时当产品真源。注意“firmware-v2”是工程名，不等于PRD M3 吧唧V2。
- 安全制造provision：独立随机设备key、后台映射、注入回执；挂失/解绑/补领不删宠物，换主人旧事件无收益。
- 两台吧唧 + 两部Android + 可达TLS后台，测绑定、断连、离线照料、掉电恢复、ACK丢失、CAS冲突、换主人和撤回。
- 完成后台定位原生插件/Manifest/桥接/授权与queue接线；替换旧测试口径，追加锁屏、权限拒绝、系统杀进程、清除/logout、旧generation隔离验收。
- 统一当前状态矩阵，建立自动回归与release构建；补备份恢复、清除策略与故障指标。
- 3D多品种与服饰、时间环真实数据、PMIC/IMU/LCD、触摸时延及典型佩戴功耗独立验收，不用旧渲染器帧率证明V2。

交付门禁：无重复结算/丢档/越权；设备key无泄漏；后台定位不补造轨迹；真机记录与回归报告可追踪。

### M2-B：遇见确认 + 图鉴基础（建议2周）

- 当前V2补双角色BLE发现、匿名发现标识、RSSI迟滞与真机标定；“约1m/3m”不是准确测距或密码学证据。
- 扫码兜底优先打通一条真实链路；敲暗号为主、连点第二的优先级须Q13复核。实体键能力Q14待真机确认，触摸作备用，不擅自复用PWR关机长按。
- 敲暗号纯策略：4–8下、停1.2s收尾、5s跟随、15s会话、归一间隔≤15%、总时长差≤30%；数字是PRD初值，不是实测定案。
- 连点：8外点+1中心、至少4点、顺序一致；去抖、最大长度、重复点、重试/中断行为另行确认。
- 服务端会话绑定双方设备/主人/随机nonce/有效期/双方证明；幂等提交与恢复。单条MEET、相同节奏或普通连接都不能直接加好友。
- 好友：默认宠物信息，联系方式后置双同意；24h解除、拉黑举报、未成年保护先定规则。
- 图鉴先汇总6品种、原愿望印章与毕业谱系；社交资产状态从权威账本读取。

门禁：双人成功、取消/超时/掉线/多设备竞争、单边确认、重放、远端伪造、解除/拉黑有自动与双机用例。

### M2-C：礼物、交换与玩家生蛋（建议3–4周）

- 新增social/collection/economy/breeding业务域，保留模块单体。协议先冻结再分端开发；不用微服务分散当前复杂度。
- 社交资产从完整游戏save分离为云端权威实例/所有权/来源/锁定/交易ledger；客户端PUT save不能新增社交/付费权益。
- 交换事务：双方锁定资产→双向同意→同一短事务变更所有权/写账本→回执；防双花、重复、与第三人并发、取消和超时解锁。礼物记录运输状态，下次真实遇见交付，不改成系统邮件。
- 规则配置化：半随机赠礼、新连接收益高于重复、重复收益衰减、冷却、给予者激励；精确概率/额度未定时不编造。
- 技能互学先定技能目录、养成路径、关系门槛、概率与上限，再做原型/试养。
- 生蛋不是替换NPC名字：双方真实父母授权、成年/家庭容量、冷却/消耗、取消退款、父母快照、后代唯一ID与归属、基因规则、毕业/解绑冲突需先决策；server生成随机结果并持久化，重试不重抽。
- 图鉴展示来源、友谊印章、交换历史与世代谱系；旧存档无损迁移。

门禁：经济守恒/合法生成、幂等唯一结算、玩家隔离、崩溃回滚、跨端一致、重复试验不刷奖励；真实双机端到端闭环完成。

### 并行专项：吧唧麦克风、语音、环境感知

必须分三层，不能以VOICE页面或收音动效冒充实现：

1. **麦克风采集底座**（建议1周验证）：ES7210/I2S双麦、采样率/通道、RAM环缓冲、采集停止/清零、播放回声、实时指示、低电/撤回停止；先确认板载/外接喇叭通路。
2. **离线语音与主动对话**（建议2–3周）：AFE/VAD/降噪/AEC→唤醒词/30–50命令→本机猫叫/动作；压缩主动语音BLE→手机本机ASR→逐次同意文本云理解→动作/气泡，禁止默认把音频上传云。测1m命令≥90%、唤醒≤1s及共存功耗。自定义唤醒词和手机离线ASR可用性需先技术验证。
3. **环境感知专项**（建议1–2周PoC，可与上层并行）：端侧声学特征/小模型分类安静、交谈、嘈杂、音乐，含UNKNOWN、置信度、平滑和低频采样；不转写、不识别人、不存/传原始音频。先做真实标注样本、混淆矩阵、CPU/RAM/电流测量；准确率、误报、占空比、分类标签TTL目标待确认。

**Q9合规已由用户确认通过，环境感知列入M2正式开发专项，不再等待合规拍板。** 先完成1–2周端侧分类验证，再安排1–2周三端集成：独立环境授权、吧唧收音指示与设置、标签/时间/置信度传输、App生活展示、后台仅接收获授权标签并执行七天TTL/撤回清除。当前HTTP四布尔授权无环境独立项，需兼容扩展契约，不能复用主动麦克风授权。保留端侧处理、不存传原始环境音频、不转写谈话、不识别人、未成年保护与撤回立即停采要求；指示灯能力与替代实现需工程确认。是否具备上线条件以分类效果、低功耗和端到端验收为准，而非仅有PoC。

### M2-D：线下试养与可选Fate（建议2–3周，部分观察跨周）

- 用约10台安全provision样机、20–50名受试者验证陌生人遇见、送礼运输、交换、生蛋和毕业谱系；观察2–4周新鲜感回落，记录D7/D14/D28、确认完成率/耗时、重复朋友收益、留存与骚扰反馈。
- 样本量小只做方向判断，不宣称因果证明；M2留存进入M3阈值需事先定义，不能套用或新造PRD未给的阈值。
- Fate独立feature flag默认关闭。现有加速度mg读取不等于姿态角：先做佩戴静止基线、倾斜估计、时间对齐和广播功耗；≥8°、差≤3°、0.3s为初值。每日上限/误报容忍待确认。

## 4. 自研硬件线（从M2-A并行）

- PRD M2要求自研AMOLED吧唧V1，当前微雪板只是打样平台；须有硬件/结构owner。
- 先冻结屏幕/芯片、电池续航目标、按键、指示灯、喇叭、触觉/NFC需求和BOM；“碰一碰”若指NFC，当前板无NFC，不能用扫码或暗号宣称已完成NFC。
- BLE/语音/渲染共存实测后再决定是否换P4或别的主控，不因旧PRD候选直接换芯片。
- 原理图/PCB/结构→小批样机→功耗/温升/佩戴/充电/天线验证→制造注入与维修挂失。供应商打样周期不纳入软件周数承诺。

## 5. M3 吧唧V2（M2留存达标后，建议另立6–10周预算）

- 数字换装真实付费：服务端商品/订单/支付回调验签/幂等权益、退款与跨设备恢复；不让客户端save决定付费权益。
- 订阅与AI额度：Q12厂商/公司套餐权限/BYOK先定案；费用预算、免费限次、超限离线，密钥不得写前端。
- 换壳/限定款：结构、供应链、SKU与售后同步；社团/地域资产先定受控场景与位置隐私，不开放全城捞人。
- M2已包含4–6维人格漂移、真实事件记忆和主动表达，宠物日记/周报Should也在M2追踪；M3只扩展AI套餐、收费护栏与经单独同意的长期记忆。不能把M2基础能力默移M3，也不能复制生活七天摘要永久存储。
- OTA固件与资产包在M2实现并验证双槽/签名/回滚；M3发布继续保持该门禁，另补release签名、支付/资源授权、年龄保护、监控与恢复。

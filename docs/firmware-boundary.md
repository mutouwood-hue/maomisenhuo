# 吧唧固件工程边界（方案阶段）

> 时点说明：本文保留初次盘点/方案的依据；此后已获准开始实现。当前代码、构建证据、完整 PRD 差距和真机待测项以 [开发状态](development-status.md) 为准，不能将初始“无工程”当成当前状态。


设备规格来源和 BSP 版本口径见[硬件交叉核对](hardware-cross-check.md)。用户有两块设备，目前一块可用；本轮没有连接或刷写设备。

## 负责范围

- 板级初始化、屏幕/触控、基础宠物画面、状态显示和低功耗/待机行为。
- BLE 设备身份、连接生命周期、消息收发和失败恢复；协议字段归 `protocol/` 所有。
- 本地必要设备设置/状态；不得成为宠物玩法规则的第二套权威实现。

## 不负责范围

- 复杂养成、商城/支付、长文本 AI、云端账户与社交结算由 App/未来服务承担。
- 本阶段不做定位、环境、语音或儿童个人信息真实采集；相关功能仅默认关闭的模拟规划。
- 按当前 PRD/厂商规格不把 NFC/马达作为首期资源。Waveshare 官方产品介绍称内置扬声器，板载资源图标注扬声器焊盘；每块实物的 SKU、装配和声音输出仍需检查。麦克风音频保持关闭，不采集。

## 依赖与证据闸门

- 目标板/显示：Waveshare ESP32-S3-Touch-AMOLED-1.75C；官方列 ESP32-S3R8、8MB PSRAM、32MB NOR Flash、466×466 AMOLED/CO5300 QSPI、CST9217 I²C 触控。实物 SKU/PCB 丝印待记录。
- BSP/UI 依赖：Waveshare 官方仓提供 `waveshare/esp32_s3_touch_amoled_1_75c` managed component `^3.0.0`，官方示例支持 ESP-IDF 5.5+，当前仓库 CI 说明验证 5.5.5/6.0.2 并提供 LVGL v9 demo。建议先选官方 ESP-IDF + BSP + LVGL v9 示例作为基线，记录确切解析版本/commit/lockfile；本地 ZIP v9.5 C 文件需实际检查 API 和构建兼容性。官方版本范围不是实测通过证据。
- 模型资产：先复用 Blockbench 源和授权组件库。必要时才安排已核实有资源的云端工作站建模/转换，同时交付可编辑源、手机 GLB 与固件轻量派生资产，记录来源/许可/哈希/版本/容量与实际设备预算。当前缺 `.bbmodel`/`.glb` 和渲染工具包；HTML 预览与交互 ZIP 不等于同源模型。
- 所有结论区分：PRD陈述、源码/构建证据、开发板观测。历史上板报告不转写成本机复验。
- 真机刷写、清空NVS或其他可能影响设备/存档的操作均不在资料阶段授权内。

## 首轮固件验收目标（待固件工程和设备条件明确）

1. 可复现构建并记录编译器/ESP-IDF/依赖精确版本。
2. 屏幕稳定显示测试宠物和由协议快照驱动的状态。
3. 模拟BLE链路通过协议fixtures；准备双端之后再真机验证发现、连接、重连和重复消息幂等。
4. 实测显示方向/触控方向、帧率、堆/PSRAM余量、待机电流或可观测功耗行为。
5. 故障/断开不造成宠物状态丢失；重试路径可解释。

首期按单板真 BLE 与显示/触摸/性能验收规划；第二块设备恢复可用后再独立做双板互遇。不把单板结果外推为双板通过。Mac 主机以代码、轻预览和手机/吧唧联调为主；任何云端建模算力、Blender/插件或磁盘资源须事前核实，额外收费另行批准。

# 需求追踪与首个闭环

> 时点说明：本文保留初次盘点/方案的依据；此后已获准开始实现。当前代码、构建证据、完整 PRD 差距和真机待测项以 [开发状态](development-status.md) 为准，不能将初始“无工程”当成当前状态。


状态语义：
- **PRD声明**：Notion v2.1 中的产品范围/状态，不是本地完成证据。
- **待取材**：原始规则/资产尚未落盘。
- **待决策**：需产品/平台/硬件决定。
- **本地未实现**：目录没有可验证实现。

## 首个可运行闭环建议

### A. 手机端原型基线

用户将更新版 `小橘电子宠物.html` 放在项目根目录，并确认其来自最新下载。已打开审阅并记录文件哈希；Notion embed 未提供可供逐字节比对的服务端文件字节。原型包含多个玩法模块，可作行为参考，但并非手机原生工程；需在后续实现计划里先选定平台，并从可追溯的小范围规则开始移植。

### B. Android 本地闭环

1. 手机端显示宠物及状态；
2. 用户触发一个明确的照料操作；
3. 依照原型规则更新数值/状态并显示反馈；
4. 重新打开应用后状态可恢复；
5. 清晰显示本地数据状态，不要求登录或网络。

### C. 单板固件与协议切片

1. 先在主机模拟/开发板无写入方式核验渲染工具、字体、模型预算；真机烧录须另行明确安排。
2. 固件显示与手机一致的基础宠物/状态；根据可用资产选静态精灵或低复杂度动画，不先强行上动态 3D。
3. 定义协议：`protocol_version`、`pet_id`（本地匿名 ID）、递增 `revision`、`updated_at`、状态字段、动作事件、错误码/确认；消息大小、BLE GATT/分片策略待附件/硬件仓审查后决定。
4. 手机→吧唧同步一份完整快照；重复包幂等；断开后可重试；双方显示一致版本/失败原因。
5. 首阶段建议由 Android App 在本地临时结算游戏规则、单块吧唧显示副本并回传事件，须由主会话产品负责人审批后冻结；PRD长期云端主存定位不变，正式离线事件回补/云端冲突策略尚待定义。

## 验收计划（执行阶段）

### 文档/资产验收

- 每份输入记录 Notion 页面、附件 block ID、来源文件名、版本/日期、下载时间和 SHA-256。
- 清点 ZIP 内容和 license；模型用原工具打开，并记录导出配置；HTML 检查外部依赖、存储位置及权限行为。
- 交互 ZIP、Waveshare 官方 1.75C BSP/示例、手机原型及协议版本映射到责任边界；模型/渲染工具包仍待补齐。

### 手机端验收

- 以本地原型中抽取并冻结的照料规则为基准，首次启动得到测试宠物；执行指定照料操作后反馈与规则一致。
- 关闭/重开后状态保持；重复动作行为符合原型规则；无网络亦能完成。
- 启动/运行不请求定位、运动、麦克风或环境权限；敏感能力展示为关闭/模拟状态。
- Android BLE 流程只设计用户主动触发的前台发现/连接；系统必要权限说明与最低 Android API 决策后续核验，当前阶段不弹权限框或收集数据。

### 协议/设备验收

- Android 手机和吧唧协商协议版本；正确处理合法快照、重复快照、缺字段/未知版本/校验失败。
- 首期在当前可用的一块吧唧上验证前台 BLE 连接、写入、确认、断开、重连、失败重试；状态 revision 最终一致。第二块恢复可用后才做双设备验收。
- 在目标板卡上记录芯片/内存/屏幕/触摸方向证据、帧率、内存占用和稳定性；清楚标出“模拟器测试”“固件构建”“真机连接”“真机交互”的证据等级。
- 方案阶段不连接或刷写设备；之后进行首次固件写入前由产品负责人安排真机验证窗口。任何擦除/NVS 操作另需单独确认。

### 出口标准

- 需求/协议/来源可追踪；原型规则不靠猜；本地手机演示不需云或敏感权限；固件画面与协议快照可复验；剩余风险和未测项单列。

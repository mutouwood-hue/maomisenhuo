### 3D/场景资产生产与交付（不在本次生成资产）

- 先取得并复用 PRD 所列 `pixel-cat.bbmodel`/`.glb`、本地 HTML 中现有猫模型/动画与已授权组件库；通过 PRD 的“组件库 + 配方”来组合场景。缺失的源模型优先向用户补齐，不因文件暂缺就重新造猫或重画既有视觉。
- 如模型重建/批量烘焙确有必要，可将重型建模与资产处理安排在主会话可用的云端电脑，减少用户 Mac 同时跑建模和开发的负担。执行前必须确认该环境实际有 Blender/所需插件、GPU/CPU/内存/磁盘足够、能正确读写目标格式且允许项目文件处理；不得默认云端有 GPU 或无限额度。若需额外收费计算、软件或 API，须另行明确批准后才启动。
- 交付同时包含可编辑源文件（例如 Blender/原始工程和依赖纹理）、手机端运行资产（优先复用 GLB/现有 Three.js 场景）及固件端轻量派生资产（根据官方 BSP 和实机预算选择 PCAT、裁切精灵/图集或预计算帧）。不将手机高面数资产原样塞入 ESP 固件，不把场景生成替换成静态图片生成。

- 用户 Mac 侧主要进行源码开发、轻量预览与 Android/吧唧真机联调；云端资产产物经哈希与格式校验后再传回本地。受控导入流程不引入付费服务，也不向第三方传送未授权模型。
- Android 侧单独验收随 APK 离线加载、无启动外网依赖、目标手机的帧时间/内存影响；固件侧独立测派生资源 Flash、运行 RAM、解码/动画与屏幕刷新。具体性能门槛由主会话基于真机 profile 批准，不预设没有依据的数字。

## 3. 推荐的技术路线与待冻结契约

### 产品端边界和状态主存

- **长期产品方向（PRD）**：云端是长期数据主存/校验与跨设备同步中心；App 是主要游戏操作端；吧唧是常驻陪伴显示及近场交互端。该产品定位不因第一阶段本地闭环而改变。
- **首阶段工程安排**：在尚无云端服务时，由 Android App 本地存档暂时承担游戏规则结算与单吧唧同步协调；吧唧只展示设备收到的快照并回传带序号的互动事件，不独立结算成长、喵币、礼物等。该安排是临时离线运行策略，不是将长期产品权威改为 App。
- **离线/云同步尚待决策**：明确离线时允许哪些操作、云端何时接管/确认、App 与云同时变更时按字段合并还是事件重放、版本/冲突如何提示、重复事件如何幂等、设备离线队列如何回补，以及云端回滚/迁移策略。协议需预留 `revision`/事件 ID/云端版本，但在产品决策前不假设“最后写入获胜”。
- **吧唧**：展示 App/云同步后的宠物快照，负责界面/省电/触摸/设备事件队列；不作为长期云档案的最终主存。
- **Android 优先技术路线**：建议 Kotlin + Jetpack Compose 原生界面、Kotlin domain 层承载宠物规则、Room 保存离线存档、Android BLE GATT adapter 处理用户发起的前台扫描/连接/同步。Android 官方 BLE API 支持 central 扫描并连接 GATT server；暂把“Android central/client、吧唧 peripheral/server”作为候选，取得固件仓后验证角色再冻结。最低 Android 版本和测试手机型号仍待确认；第一期不做后台扫描/保持连接，当前阶段不请求系统权限。
- **复用而非套壳/重画**：逐项从现有 JS 抽取/映射玩法规则到 Kotlin domain，并以原 HTML 的画面、布局、色彩、文案和动画作为 Compose 的对照基线，保留 ZIP 内图标、字体、音效。单文件 HTML 不作为完整应用 WebView 套壳。现有 Three.js 场景可先隔离成随 APK 本地打包的 WebGL renderer，WebView 只提供既有猫场景，不持有业务逻辑、存档或 BLE；通过窄数据/动画接口同步画面状态，禁止远程资源。缺失的 `.bbmodel/.glb` 到手并核对授权和同源关系后，再评估复用导出资产。若真机性能或 WebView 渲染与目标视觉不符，再根据同一资产与基线比较 Android 原生 3D renderer；视觉重构需要主会话审批。

### 在并行开发前先冻结的共享协议

先写与平台无关的 schema、示例 JSON/字节 fixtures 和版本策略：

1. 为无云第一切片明确一份临时 App 本地快照：`petId`、外观/衣装 ID、阶段、5项状态、货币、版本 `revision`、更新时间；吧唧收到幂等快照只渲染。后续云端主存需有显式 cloud revision/同步状态，不能把本地 revision 当云端权威版本。
2. 设备事件包括事件类型、单调序号/去重 ID、设备时间、必要参数和确认状态。评估如何外层包装现有 8 字节 legacy event（时间4+类型1+参数A1+参数B2），不破坏旧规格；增加掉电安全队列、重试、ACK、队列满处理和时钟校准。
3. 定义断连重连、消息分片/长度、版本协商、无效字段/未知版本的错误码；BLE GATT UUID、安全握手和 central/peripheral 角色要根据现有固件仓核对后定，不从 Demo 假定。
4. 约束首期只前台连接/同步，不依赖手机后台扫描。协议模拟先覆盖连上、快照、事件 ACK、重复事件、断连、重试，再接真实 BLE。

## 4. 最小跨端可运行闭环

1. App 启动本地小橘状态，执行一次「摸摸」（第一切片）或另选一项带状态变化的照料；按冻结规则更新一次并保存。
2. 手机连接一块吧唧，发送带 `petId/revision` 的外观/状态快照；屏幕状态显示相同 revision。
3. 吧唧主屏轻点小猫，发出摸摸事件；App 校验序号、结算心情/亲密记录、写入本地存档并 ACK。
4. 断开再连后设备取得首阶段本地最新快照；重复提交同一事件不重复结算。无网络、账号、定位、语音或云服务时仍能完成。该切片不裁决未来 App/云双向冲突。
5. 先主机模型/状态模拟和 BLE fake transport，再用当前唯一可用吧唧完成 Android↔单设备真 BLE 闭环；然后做单板屏幕/触摸/FPS/内存/功耗验收。目前两块中一块可用，不能声称双板互遇已测。第二块恢复可用后单独安排双设备发现、会面及重复事件验收。

此闭环不复刻整份 PRD社交/AI/相遇世界；后续从已经存在的原型功能逐块迁移。第一实体界面目标应以 HTML 开发标注和 ZIP LVGL v9 生成代码为准。

### 首阶段具体实现任务和真机验收点

1. **产品负责人先批范围**：主会话小点狗明确本次照料动作、需更新的状态字段、用户可见反馈、沿用哪些原型画面/动效、App 本地临时存档范围、BLE 事件语义和验收门槛。Codex 负责把原型行为映射成实现规格，不自行定玩法数值或改视觉。
2. **Android 工程底座**：Kotlin + Jetpack Compose 页面骨架和原型视觉 token；Room 本地存档；Kotlin domain 用可重放规则实现批准的一个照料动作；使用合成宠物数据，不启用网络 API、定位、运动、环境、相机或麦克风权限。
3. **猫场景衔接**：在已审批视觉下封装本地 Three.js 场景作为单独 renderer，给原生 App 传递宠物状态/动作指令；离线资源随包、桥接口收敛，不把整个 HTML、JS 存档和 UI 一并装进 WebView。
4. **固件可复现基线**：跟随 Waveshare 官方 1.75C ESP-IDF 示例和 managed BSP 建本项目构建，记录官方仓 commit、ESP-IDF、BSP/LVGL 解析版本；将 ZIP 中 LVGL v9.5 页面代码适配到同一基线。构建检查与 fake display 可先开展，不触碰板上 flash。
5. **跨端协议与 fake transport**：在小点狗批准后确定前台连接下的设备身份、快照、revision、事件 ID/确认、重试和断连行为；手机/固件共用 JSON/字节 fixtures，先让 BLE emulator 覆盖正常/重复/无效/断连路径。
6. **唯一可用吧唧的真机验收**：后续获准安排窗口后，对该板登记 SKU/PCB 丝印/供电状态；验证 Android 前台发现/连接和 GATT 服务；设备屏幕的 466 圆形安全区与状态快照、实际触控方向/边缘/按压时序、互动事件 ACK 和重复事件去重；测试断开/重连和 App/吧唧重启状态恢复；记录显示刷新、空闲/互动 FPS、剩余 heap/PSRAM、Flash image/分区和电流/续航基线。设备写入不在当前方案阶段进行。
7. **第二块板**：当前不可用，不是单板切片的阻塞项；恢复可用后另验双机 BLE 角色/发现、相遇距离阈值、会话安全/隐私、同一事件重复/断连和双方日志。不得用单板结果替代双板验收。

要展开为可执行的跨端契约、改变用户可见玩法/视觉、改变云端状态权威或通过验收，均由主会话小点狗审批。开发模型生成的代码和审核建议只供主会话审阅。

### 并行边界

- S1前可以并行：资产分析、Waveshare 官方仓/BSP只读盘点、已知板卡 SKU 信息登记、协议测试样例草案；不私定消息字段、游戏规则或产品视觉。
- S1后可并行：Android Compose 页面/Kotlin domain/Room；固件屏幕/输入/省电与显示快照；3D 场景隔离/既有组件库资产审计与经批准的云端资产处理；BLE simulator/QA fixtures。共享冻结 schema 和资产版本作为契约门禁。
- 串行集成点：模型/字体预算 → 固件镜像；schema → 两端 BLE 互通；真实权限/AI key/云账号 → 隐私批准后再接入。
- **产品治理**：主会话小点狗是产品总领，负责体验/范围、跨端契约审批和验收门槛，并决定是否进入下一阶段。Codex 模型只负责批准范围内的实现、方案草案和独立技术审查；不替产品负责人拍板或自行签收产品验收。
- 测试/独立审查可与实现同步准备；真实 BLE、屏幕性能/功耗、触控与扬声器输出验收排在固件和真机准备之后。模拟器不能替代。

## 6. 开发模型与产品运行时 AI 分开规划

### 用于写代码的 Codex 模型（具体建议，尚未执行）

### 产品运行时 AI（来自 PRD的候选映射，不在本期接入）

- 吧唧离线唤醒/固定命令词：候选本机识别，不调用 LLM、不传音频。
- 小猫 App 自由对话/人格：PRD候选 StepFun 3.5/3.7 Flash；仅先做 mock/provider adapter。
- 积木场景：PRD候选 StepFun 3.5 Flash，复杂地点候选 Step 5 Preview；先本地固定配方，验证组件/安全约束后再评估模型。
- 日记/周报/长期记忆：PRD候选 Step 5 Preview；属于后台云能力，晚于核心玩法与数据隐私策略。
- 所有产品模型选择、官方当前可用版本、价格/限额、儿童数据规则需立项时重核；本阶段不配置 key、不发请求、不启用付费 API。Demo 页面可能允许用户输入和记住密钥，开发包需保持此入口关闭。

## 7. 开发前必须补齐/决策项

1. Android 已定为先行平台。后续确认最低 Android OS、测试手机型号以及 iOS 是否进入后续阶段。
2. 用户有两块吧唧、目前一块可用。后续记录每块的 SKU/PCB 丝印、电池是否安装、扬声器实物和声音状态、USB/串口条件；官方网页规格不替代当前设备复验。
3. 资产：补齐页面当前版本的 `pixel-cat.bbmodel`、`pixel-cat.glb`、吧唧渲染工具包 ZIP、触控引导 HTML、说明/字体许可。它们已在最新 Notion 页面列出，但项目目录未找到；这会阻塞同源猫模型管线。
4. 固件：以 Waveshare 官方当前 ESP-IDF 示例仓为硬件基线，并确认项目自身固件仓/commit；本地 ZIP 只有 screen C骨架，没有 BLE service 或完整硬件 App 工程。
5. 产品同步目标：PRD长期云端主存方向保持不变。确认首阶段 App 本地暂存/结算策略，以及离线事件回补、云端接管时的冲突合并和用户提示；在规则未定前只做不接云的单机闭环，不将 App 本地权威扩展为正式云端同步契约。
6. 面向儿童的年龄与真实账号/数据范围，等功能要采集任何真实个人数据时再决定；现在使用虚构角色/存档。

## 8. 明确暂不纳入

不重做原型视觉、不实现整份社交功能、不把历史 M1 记录标为本机复验；不请求位置/运动/环境/麦克风/相机权限；不连接产品云、不输入 token/key、不调用运行时模型 API；不刷写/擦除设备或真实存档；不默认启用云 GPU/付费工具，不购买、推送或发布。

# 吧唧 UI 实现与原始 23 屏的对应

输入为用户本地交互开发包 `badge_spec.json` v0.3.0。`main/assets/ui-contract-source.json` 保存 ZIP/spec 哈希和全部 23 屏名字/手势；`tools/extract_ui_contract.py` 可重复提取配色和基础触控阈值。没有导入原开发包中的历史硬件结论、示例数值或旧二进制事件。

当前新增源码尚须主集成串行构建并完成真机验证，不能视为已上板验收。稳定候选产物没有被这些源码修改覆盖。

本轮用户允许彩色场景，因此主屏采用低亮度彩色渐变：颜色只随真实快照的 mood/energy 变化，不把它当作出游、位置或行为。状态/设备/自检页保留高对比深色底，按钮与文字布局遵循圆形 safeR=212。原猫只做两帧切换与轻量位移，不称完整 3D 动画。

导航为：主屏下滑到状态、状态上滑返回；状态按钮进设备；设备右滑回状态；触摸自检右滑回设备。各页都有实际返回入口。220ms 切页期间屏蔽新操作；没有复制尚未实现的跟手拖拽、阻尼和高级过渡。

基础识别使用生产 `badge_gesture.c`：轻点 <=300ms 且整个轨迹最大位移 <12px；长按 >=600ms 且位移 <12px；滑动最终位移 >=50px 且 <=500ms。滑动/长按结束不产生摸摸。`tools/test_gesture.py` 由主集成串行执行轻量 host 回归，结果仅证明分类器边界，触控方向/边缘/手感仍需真机。

确认提示严格来自真实路径：本地 NVS 排队成功才显示“摸摸已保存”；手机 applied/duplicate ACK 对应事件被成功持久删除后才显示“手机已确认”；收到并接受真实快照后才显示“最新状态已同步”。相关只读 RAM 观察计数不改变 wire 或 NVS 布局。开机恢复的历史状态只标为上次状态，不制造新的同步反馈。
